# 故障排除

按你看到的症状找对应小节。每条修复都以一个可执行动作结尾；做完仍不解决，保留 `$DSH_HOME/prompt-hub/` 目录和 Harness 日志再排查。

## 侧栏里没有「提示词中心」

最常见的原因是插件没启用，或 DSH 版本不在支持范围。

1. 打开插件管理器，确认 dsh-prompt-hub 已安装并处于启用状态。
2. 确认 Harness 版本为 0.2.2-rc.3 或更高的 0.2.x。0.3.0 及以上不在 `engines.dsh` 范围内。
3. 重新安装本目录的 bundle，然后重新加载窗口。
4. 查看 Harness 启动日志或浏览器控制台里是否有 `dsh-prompt-hub` 的加载错误。

## 输入框左侧没有「插入提示词」按钮

1. 确认插件已启用，DSH 版本为 0.2.2-rc.3 或更高的 0.2.x。
2. 重新加载窗口，再打开一个对话确认按钮出现。
3. 检查浏览器控制台是否有 `conversation.input.left` 插槽注册失败，或输入框上下文（`useInput` / `inputActions`）缺失的错误。
4. 控制台没有错误但仍不显示时，重新安装 bundle 后再试。

## 面板一直显示「正在读取」，或出现「读取失败：…」

通常是对 `/dsh-prompt-hub/data` 的请求失败，或数据文件不可读。

1. 点击面板里的 **重试**。
2. 检查 `$DSH_HOME/prompt-hub/` 是否存在，当前用户是否有读写权限。`$DSH_HOME` 默认是 `~/.dsh`。
3. 若 `data.json` 无法解析，插件会尝试用最新备份自动修复；修复不了时，按 [理解提示词库的存储与备份](storage-and-backups.md) 里的“手动恢复一份旧备份”操作。
4. 查看 Harness 日志里该路由返回的状态码：403 是来源校验失败，400 是文档结构非法，404 说明路由没有注册。

## 点「管理提示词」没有反应，或日志出现 `cannot get property "layout" without inject`

原因是浏览器半边没有声明 `layout` 服务，常见于旧版 `client.js` 或缺少 `inject` 声明。

1. 确认安装的是 1.2.0 的 `client.js`，且 `exports.inject` 含 `slots`、`locale`、`layout`。
2. 重新安装 bundle，然后重新加载窗口。
3. 再点一次 **管理提示词**，确认能跳到主面板。

## 看到「提示词库已在其他窗口更新，你的修改未保存。」

另一个窗口或 AI 工具在你读取之后先写入了库，修订号不匹配。

1. 点击横幅右侧的 **关闭**。
2. 重新打开 **提示词中心**，确认列表已经是最新内容。
3. 重做刚才的修改并 **保存**。
4. 需要同时用 AI 改库时，等一方完成后，再操作另一方。

## 出现「保存失败：…」

1. 阅读提示里的具体原因：标题或内容为空、正文超过 100,000 字符、分类或提示词数量超限。
2. 按提示缩短正文、补上标题，或删减条目。
3. 如果是磁盘或权限错误，确认 `$DSH_HOME/prompt-hub/` 可写后，点 **保存** 重试。

## 出现「导入失败：…」

1. 确认文件是 JSON 对象（`{ … }`），不是数组或纯文本。
2. 确认 `categories` 和 `prompts` 都是数组；让来源方用 **导出 JSON** 重新生成文件。
3. 文件过大或条目超限时，先拆分或删减，再 **导入**。
4. 换一个已知可用的 JSON 文件试导入，确认不是当前文件损坏。

## 删除时没有确认对话框

**删除前确认** 被关掉了。

1. 打开 **设置**。
2. 勾选 **删除前确认**。
3. 关闭设置，再试一次删除。

## 插入的提示词覆盖了已有草稿，或没有空行

**插入方式** 被设成了 **替换**。

1. 打开 **设置**。
2. 把 **插入方式** 改为 **追加**。
3. 回到输入框，重新插入一次。

## 点「复制内容」没有出现「已复制」

浏览器拒绝了剪贴板写入，插件不会弹错误。

1. 检查浏览器和系统的剪贴板权限，允许 Harness 写入。
2. 仍不行时，用 **导入导出** 里的 **导出 JSON** 取走内容。
3. 再点一次 **复制内容** 验证。

## 变量没有被替换

1. 确认正文里是 `{{名称}}`，不能用单花括号；名称两侧允许空格。
2. 回到面板 **编辑** 提示词，修正占位符后 **保存**。
3. 重新插入，在 **填写变量** 里填入值；留空会保留占位符。
4. 再次插入，确认替换结果。

## AI 报 `no category named` 或 `no prompt with id`

1. 让 AI 先 `search` 或 `list`，拿到准确的分类名和条目 id。
2. 分类不存在时，先让它 `create_category` 建同名分类。
3. 用准确的名称或 id 重新执行原操作。

## 列表只显示了一部分提示词

面板一次最多渲染 200 条。

1. 看列表底部是否有“另有 N 条未显示”。
2. 用 **搜索提示词** 或左侧分类缩小范围。
3. 需要浏览全部时，按分类逐个查看。

## 面板是空的，但 `data.json` 里有提示词

Harness 解析到的 `$DSH_HOME` 和你查看的目录不是同一个。

1. 确认 Harness 实际使用的 `$DSH_HOME`：`dshHomePath` 服务优先，其次 `DSH_HOME` 环境变量，最后 `~/.dsh`。
2. 退出 Harness，把旧数据的 `prompt-hub` 目录复制到实际 `$DSH_HOME` 下。
3. 重新启动 Harness，打开 **提示词中心** 确认内容。

## 数据看起来回到了更早的版本

`data.json` 损坏后会从备份自动修复，用的是最近一份可读备份，可能缺少最后几次修改。

1. 打开 `$DSH_HOME/prompt-hub/backups/`，按修改时间确认有没有更新的备份。
2. 按 [理解提示词库的存储与备份](storage-and-backups.md) 里的“手动恢复一份旧备份”换入合适的版本。
3. 恢复后先 **导出 JSON** 留一份新备份。

## 仍无法解决

1. 保留 `$DSH_HOME/prompt-hub/` 整个目录，不要删除 `data.json` 或 `backups/`。
2. 记录 Harness 版本、插件版本 1.2.0、复现步骤，以及日志里 `/dsh-prompt-hub/data` 的状态码。
3. 把信息反馈给插件维护者，并说明是否出现过冲突横幅或“读取失败”。
